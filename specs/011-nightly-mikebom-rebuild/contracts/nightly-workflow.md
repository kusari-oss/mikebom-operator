# Contract: `.github/workflows/nightly-mikebom-bump.yml`

Machine-checkable interface for the nightly-detection + PR-opening workflow.

## Triggers

```yaml
on:
  schedule:
    - cron: '17 3 * * *'   # 03:17 UTC daily. Off-hour to avoid collision with typical Kusari deploy windows.
  workflow_dispatch:
    inputs:
      dry_run:
        description: "Detect + bump locally but do NOT push or open PR"
        required: false
        type: boolean
        default: false     # Default: real run when maintainer clicks Run.
```

## Permissions (workflow-level)

```yaml
permissions:
  contents: write         # Push bump commit to bot branch
  pull-requests: write    # Open PR + enable auto-merge + apply label
  issues: write           # File / comment failure issues (FR-012, FR-016)
```

No `id-token: write`. This workflow never calls cosign; `release.yml`
retains that role.

## Concurrency

```yaml
concurrency:
  group: nightly-mikebom-bump
  cancel-in-progress: false
```

## Job graph

```text
detect ──► bump ──► open_pr
   │        │
   │        └── (on any failure) ──► signal_failure (composite step in same job)
   │
   └── (early no-op) ──► summary_only (composite step)
```

Single-job workflow (`bump` runs on the same runner instance so bumped
files persist through PR-opening).

## Step-by-step contract

Every step below is either implemented in a shell script under
`.github/scripts/nightly-*.sh` (invoked via `run: bash .github/scripts/…`)
or is a `uses:` reference to an existing SHA-pinned action.

### 1. `checkout`
- **Action**: `actions/checkout` (SHA pinned, reused from `release.yml`).
- **`fetch-depth: 0`** — needed for reading `git tag -l` history.
- **`token: ${{ secrets.GITHUB_TOKEN }}`** — explicit to enable subsequent
  push.

### 2. `install-yq`
- **Action**: `mikefarah/yq` (SHA pinned, reused from `release.yml`).

### 3. `detect`
- **Runs**: `bash .github/scripts/nightly-detect.sh`
- **Env**: `MIKEBOM_REPO=kusari-oss/mikebom`, `OPERATOR_REPO=${{
  github.repository }}`, `GH_TOKEN=${{ secrets.GITHUB_TOKEN }}`.
- **Reads**: `charts/mikebom-operator/values.yaml`, `gh api`, `docker
  manifest inspect`, `gh pr list`.
- **Writes to `$GITHUB_OUTPUT`**:
  - `decision`: one of `noop_up_to_date`, `noop_open_pr_exists`,
    `noop_known_bad`, `noop_manifest_pending`, `noop_no_operator_baseline`,
    `should_bump`. `noop_manifest_pending` covers the spec edge case where
    the mikebom release is tagged but the multi-arch image hasn't yet been
    pushed to ghcr.io — a benign race that resolves itself on the next
    nightly run.
  - `current_pin`: e.g., `v0.1.0-alpha.57`.
  - `latest_mikebom`: e.g., `v0.1.0-alpha.58`.
  - `next_operator_tag`: e.g., `v0.1.0-alpha.2`.
  - `open_pr_number`: only when `decision=noop_open_pr_exists`.
- **Writes to `$GITHUB_STEP_SUMMARY`**: the decision table (see
  data-model.md "Summary line format").
- **Exit code**: 0 on any of the noop decisions or `should_bump`. Nonzero
  only on hard failure (network error, gh CLI error, malformed values.yaml).

### 4. `bump` (conditional on `decision == should_bump`)
- **Runs**: `bash .github/scripts/nightly-bump.sh`
- **Env**: `MIKEBOM_OLD=<current_pin>`, `MIKEBOM_NEW=<latest_mikebom>`,
  `OPERATOR_NEW=<next_operator_tag>`.
- **Modifies files** (in-tree):
  - `charts/mikebom-operator/values.yaml` — `mikebom.image` string
  - `charts/mikebom-operator/crds/namespacescan.kusari.dev_v1.yaml` —
    description string, then regenerated from source via
    `cargo run --bin mikebom-operator-ctl -- crd`
  - `crates/operator/src/crds/namespace_scan.rs` — doc-comment
  - `crates/operator/src/scan_job/mod.rs` — 2 unit test fixture strings
  - `docs/crd-reference.md` — 3 example YAML blocks
  - `examples/namespacescan.yaml`
  - `e2e/tests/{job_status_feedback,reconciler_failover,reconciler_skeleton,reconciler_spawns_job,scan_job_dryrun,schedule_honoring}.rs`
  - `Cargo.toml` — `[workspace.package].version`
  - `charts/mikebom-operator/Chart.yaml` — `version` + `appVersion`
- **Excludes** (never touched): `specs/003-scan-job-builder/**`,
  `specs/004-pvc-backend/**` (frozen historical spec artifacts).
- **Validates**: runs `cargo fmt --check`, `cargo build --workspace`,
  `cargo test --workspace --lib` locally on the runner before returning
  success. E2E tests are NOT run here — they gate at PR-CI time.

### 5. `open_pr` (conditional on `decision == should_bump && !dry_run`)
- **Runs**: `bash .github/scripts/nightly-open-pr.sh`
- **Env**: `MIKEBOM_NEW`, `OPERATOR_NEW`, `GH_TOKEN`, `PR_LABEL=nightly-mikebom-bump`.
- **Actions**:
  1. `git checkout -b automation/nightly-bump/<MIKEBOM_NEW>`
  2. `git add …` (specific paths from step 4)
  3. `git commit -m "$(cat <<EOF\nchore(nightly): bump mikebom to <MIKEBOM_NEW> and operator to <OPERATOR_NEW>\n\nAuto-generated by nightly-mikebom-bump.yml. See {run_url}.\n\nNightly-Bump-Target: <MIKEBOM_NEW>\nEOF\n)"`
  4. `git push origin HEAD`
  5. `gh pr create --title "chore(nightly): bump mikebom to <MIKEBOM_NEW> and operator to <OPERATOR_NEW>" --body-file /tmp/pr-body.md --label nightly-mikebom-bump --base main`
  6. `gh pr merge <number> --auto --squash --delete-branch`
- **PR body schema** (`/tmp/pr-body.md`):
  ```markdown
  ## Nightly mikebom bump

  Bumps the pinned mikebom image from `<current_pin>` → `<latest_mikebom>`
  and cuts operator release `<next_operator_tag>`.

  ### Verification (performed by this workflow)
  - [x] mikebom `<latest_mikebom>` GitHub Release exists
  - [x] multi-arch manifest present on `ghcr.io/kusari-oss/mikebom:<latest_mikebom>`
      (amd64 + arm64)
  - [x] `cargo build --workspace` — pass
  - [x] `cargo test --workspace --lib` — pass

  ### Mikebom release notes (excerpt)

  <first 2000 chars of release body>

  ### What happens on merge

  On green CI + Kusari Inspector, this PR auto-merges. The follow-up
  `tag-on-nightly-merge.yml` workflow detects the merged commit's
  `Nightly-Bump-Target:` trailer and pushes tag `<next_operator_tag>`,
  which triggers `release.yml`.

  ---
  🤖 Generated by [nightly-mikebom-bump.yml](<run_url>)
  ```

### 6. `signal_failure` (composite `if: failure()` step)
- **Runs**: inline script that:
  1. Builds `failure_signature = "<GITHUB_JOB>_<GITHUB_STEP>_<exit_code>"`.
  2. `gh issue list --state open --label nightly-mikebom-bump/failure --search "in:title <step_name>"` — checks for existing.
  3. If found: `gh issue comment <n> --body "<annotation>"`.
  4. Else: `gh issue create --title "[nightly] failed at <step_name>" --body-file /tmp/issue-body.md --label nightly-mikebom-bump/failure`.
  5. `echo "::error::Nightly failed at <step_name>. Issue: <url>"` (workflow annotation).

## Outputs (workflow-level)

None. All state is communicated via the created PR, filed issue, or run
summary.

## Failure semantics

| Failure class | Signal channel | Repo state after |
|--------------|---------------|------------------|
| Network / API error at `detect` | issue + annotation | clean (no bump attempted) |
| Manifest verification fails | issue + annotation | clean |
| `bump` cargo fmt/build/test fails | issue + annotation | clean on the bot branch; PR NOT opened; branch cleaned up |
| PR opening fails (branch push rejected) | issue + annotation | orphan branch may exist on remote — issue body includes cleanup command |
| Auto-merge enable fails | issue + annotation; PR left open | requires maintainer intervention |
| `signal_failure` step itself fails | annotation only (issue create failed) | annotation is the last-resort channel |

## Non-goals for this workflow

- **Does NOT sign anything**. `release.yml` retains sole signing authority.
- **Does NOT modify `main` directly**. Only PR-based delivery.
- **Does NOT poll for auto-merge completion**. Handoff to
  `tag-on-nightly-merge.yml` via commit trailer.
